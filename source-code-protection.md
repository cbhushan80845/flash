# Source Code Protection Plan

Last updated: 2026-05-23

## Recommended Sharing Model

Use one public portfolio link that contains only the project summary, QA approach, test coverage, screenshots, and execution results. Keep the real application and automation source code in a private repository.

## What To Share Publicly

- Project overview
- Tech stack
- Automation architecture summary
- Test coverage table
- Test execution result
- Screenshots or short demo video
- Resume bullet and LinkedIn post text

## What Not To Share Publicly

- Full source code
- Environment files
- Database credentials
- API keys or tokens
- Test user passwords
- Internal package structure screenshots showing too much code
- Complete business logic

## Best Link Options

| Option | Good For | Code Safety |
| --- | --- | --- |
| Public GitHub showcase repo | Resume and LinkedIn link | High, if it contains docs only |
| Google Drive PDF | Recruiter-friendly portfolio | High |
| LinkedIn Featured PDF | Direct profile visibility | High |
| Private GitHub repo | Interviewer review by invitation | Medium to high |

## Recommended Final Setup

1. Keep this project repository private.
2. Create a separate public repository named `cob-platform-qa-showcase`.
3. Upload only the files from this `portfolio-showcase` folder.
4. Add the public showcase repository link to resume and LinkedIn.
5. Share private source access only during serious interview rounds.
